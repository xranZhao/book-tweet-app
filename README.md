# 推文助手

手机 PWA：选书 → 完整阅读 → 决定是否生成推文 → 编辑 → 云上传。

## 使用

- 设置中填写 DeepSeek API Key。默认阅读模型 `deepseek-flash`，写作模型 `deepseek-v4-pro`。
- 导入 TXT、Markdown、EPUB 或 ZIP。ZIP 读取最大的 TXT/Markdown 文件。
- TXT/Markdown 与 ZIP 内文字统一识别 UTF-8、GB18030、带 BOM 的 UTF-16。明显乱码会拦截；阅读前先核对开头、中间、结尾预览，再勾选确认。
- 约 40 万字符以内一次提交全文，只生成短看文卡；更长的书每约 40 万字符一批提取简短互动素材，全部保存后汇总。不是抽样。边界优先在换行处切分，不遗漏原文。此阈值按当前默认 DeepSeek 模型留有上下文余量，不保证任意自定义模型都支持。
- 看文卡：100～200 字故事简介、最多三个有原文出处的互动片段、一句口味提醒，总计目标 400～600 字；不生成完整剧情和学术分析。素材不足时少给，不凑场景。字数、片段选择由提示词约束，实际生成质量仍需人工核对。
- 普通流程点一次自动继续；暂停后完成当前调用再停。关闭页面或网络失败可能丢失当前未返回的调用，已完成批次保留。模型长度截断后部分输出保留，手动继续会产生新的 API 费用，不自动无限重试。
- 旧笔记不参与新版汇总，重新阅读前旧报告、笔记、已有推文另存历史快照；旧稿可继续编辑与上传。乱码原文需重新导入文件，应用无法从旧乱码恢复丢失的原字节。
- 点击生成后才调用写作模型，输出不超过 800 字；可以直接修改标题、正文，文字自动保存在本设备。
- 云上传沿用阿野收件箱的 GitHub Contents API。填写同一个 GitHub Token、仓库和目录，默认 `xranZhao/aye-article-inbox` 的 `0-原始文稿/磕学家`。旧版默认上传目录会自动迁移到此目录；第一篇上传时自动创建文件夹，已有云端稿件不移动。上传的是编辑后的 Markdown；同一稿件再次上传前确认覆盖。电脑端继续使用阿野工作流下载处理。
- 排版不在 PWA 内，原有排版脚本与风格指南保留。

## 数据与费用

正文、笔记、草稿使用 IndexedDB；首次打开迁移旧版草稿与历史，旧 localStorage 数据不删除。历史可打开编辑。清除网站数据会删除本地内容；云上传成功的稿件保存在 GitHub。

新一轮阅读费用预估使用中文字符约 0.6 token，加简短素材及看文卡的假设输出用量，不是报价或费用上限；不包括写作、续接、重试和极长书的额外压缩，仅供参考。记录接口实际 token 用量，并按内置单价估算人民币费用；未接入节假日日历，节假日高峰估值可能偏高，以 DeepSeek 账单为准。模型使用非思考模式控制费用，不自动重试收费请求。全文覆盖不等于模型逐字准确理解；模型仍可能漏掉情节或误选片段，应人工核对。

## 验证

使用现有 Chrome 与 Playwright 模拟接口验证：实际 GB18030《Immer》与 ZIP 导入、UTF-8/UTF-16 解码、乱码拦截、全文一次调用、超长书分批全覆盖、旧笔记隔离、历史备份与不推荐记录；先前版本另已验证编辑保存、Markdown 上传及数据迁移。未消耗真实模型余额或写入真实云端测试稿。
